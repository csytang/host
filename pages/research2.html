    Secure and Verifiable Agentic Software Engineering

    Artificial intelligence systems increasingly generate, modify, test, repair, and operate software. The central challenge is no longer whether an AI system can produce code, but whether its outputs and actions can be trusted in real software environments. Our group combines program analysis, software security, empirical software engineering, mobile ecosystem analysis, and large language model (LLM)-based automation to make software behaviour testable, agent actions governable, and deployment decisions evidence based.

    Core question: When should AI generated software be trusted, when must it be tested, and when should it be rejected?

    Three Core Research Questions

    The agenda is organised around three decisions that trustworthy AI-assisted software systems must support: whether an artefact is valid, whether an action is authorised, and whether the available evidence is sufficient for accountability.

    01

    When should AI generated software be trusted?

    Research problem

    Syntactically correct code can still contain behavioural defects, compatibility failures, security vulnerabilities, weak tests, or incorrect assumptions about its operating environment. Trust therefore requires evidence about what generated code and patches actually do, not only whether they compile or pass a narrow test.

    Technical approach

    We develop semantic analysis and verification methods that combine static analysis, dynamic analysis, taint analysis, software testing, configuration analysis, and LLM-assisted reasoning. These methods examine program paths, environmental constraints, test adequacy, and patch behaviour before an artefact is accepted.

    Selected evidence

    • Artemis — LLM-assisted inter-procedural, path-sensitive taint analysis (OOPSLA 2025)
    • LLM-CompDroid — repairing configuration compatibility bugs in Android applications (TOSEM 2025)
    • Beyond Coverage — automatic test suite augmentation for enhanced effectiveness (OOPSLA 2026)

    02

    Whose intent should control an AI agent’s permissions?

    Research problem

    Authenticating a user or agent is not sufficient. A system must determine which source of intent caused a tool call, whether the action matches the user’s request, whether its scope is authorised, and whether its consequences require confirmation. This becomes critical when coding agents use repositories, package managers, files, command-line environments, application programming interfaces, and external services.

    Technical approach

    We study permission semantics, intent origin, action scope, consequence awareness, sandboxing, audit logging, and runtime governance. For tool-using agents and Model Context Protocol (MCP) tools, the aim is to constrain execution, trace data flows, detect malicious dependencies or leakage, and preserve evidence of what authority was exercised.

    Selected evidence

    • MCP-SandboxScan — WebAssembly-based secure execution and runtime analysis for MCP tools (CoRR 2026)
    • FuseChain — runtime evidence reconstruction for software supply-chain attacks (CoRR 2026)
    • Third-party library and dependency analysis — Android software ecosystem evidence (ASE 2019; TSE 2021)

    03

    What evidence is required to hold AI assisted software systems accountable?

    Research problem

    A successful output alone does not demonstrate reliability. Evaluation must also consider correctness, introduced vulnerabilities, reproducibility, provenance, runtime behaviour, human review effort, inference cost, and environmental cost. Without this evidence, failures cannot be diagnosed consistently and deployment decisions remain difficult to justify.

    Technical approach

    We study benchmark construction, execution traces, workflow reliability, human oversight, and runtime evidence reconstruction. Evaluation connects observable behaviour to failure taxonomies and cost-aware measures so that claims about an agentic workflow can be reproduced, compared, and reviewed.

    Selected evidence

    • SecBenchLLM — an ongoing benchmark project for security evaluation of LLM-assisted software systems
    • LLM EcoBench Lite — an ongoing benchmark project for cost- and carbon-aware evaluation
    • Characterizing Large Language Model Agentic Workflows: A Study on N8n Ecosystem (arXiv 2026)

    Research Foundations

    Three technical foundations support the agenda and connect questions about code, permissions, and evidence.

    Program Analysis and Semantic Validation

    Static analysis, dynamic analysis, taint analysis, configuration analysis, software testing, semantic reasoning, and patch validation establish whether software behaviour matches its stated intent. Together, these methods move assessment beyond syntax and surface-level test success towards program paths, environmental assumptions, compatibility constraints, and observable outcomes.

    Runtime Governance and Software Ecosystem Security

    Sandboxing, permission control, provenance, supply-chain security, runtime monitoring, and evidence reconstruction govern how agents interact with tools and environments. This foundation also addresses data leakage prevention, malicious dependency detection, capability boundaries, and the audit records needed to explain actions after execution.

    Empirical Measurement and Benchmark Design

    Large-scale empirical studies, benchmark construction, reliability measurement, cost-aware evaluation, reproducibility, human oversight, and failure taxonomy construction provide a disciplined basis for comparison. They reveal where systems fail, what review effort is required, and whether observed gains persist across tasks, environments, and repeated executions.

    Application and Validation Environments

    We develop general mechanisms and validate them in software environments where permissions, dependencies, failures, and human decisions can be observed under realistic constraints.

    Mobile and Android Ecosystems

    Mobile ecosystems provide realistic environments for studying permission boundaries, private data transmission, third-party dependencies, application repackaging, compatibility failures, malicious components, and software supply-chain risks. Their layered platforms and distributed stakeholders make hidden assumptions and consequences particularly visible.

    • WhisperCatcher — unauthorised and encrypted private data transmission (ICSE 2026)
    • Mobile Sharing Service Abuse (WWW 2022)
    • App Link Attack (ESEC/FSE 2020)
    • Android app bundle analysis (TSE 2025)

    Computational and Developer Workflows

    Notebooks, scripts, automation pipelines, low-code platforms, agentic workflows, and developer tools provide realistic environments for studying validation, logging, exception handling, recovery, permission boundaries, and human oversight. They expose how locally plausible steps combine into reliable or fragile end-to-end behaviour.

    • Characterising Bugs in Jupyter Platform (EASE 2025)
    • N8n agentic workflow study (arXiv 2026)
    • Low-code programming with traditional and large language model support (JSS)

    Research Architecture

    Trust is not assumed from a plausible output. It is produced through a sequence of analysis, constrained action, evidence, and evaluation.

    Selected Research Programmes

    The agenda is pursued through three connected programmes, each linking a decision problem to concrete methods and research assets.

    Programme 01

    Semantic Validation for AI Generated Software

    Objective: determine whether generated, repaired, or tested software behaves correctly under realistic program and environment constraints.

    Technical methods

    • Static and dynamic program analysis
    • Test generation and augmentation
    • Configuration and patch validation

    Selected assets

    • ChatGPT versus search-based software testing (TSE 2024)
    • Assessing the quality of code generation by ChatGPT (TSE 2024)
    • Coverage goal selection (TSE 2024)

    The next research frontier is an end-to-end validation chain that preserves evidence across generation, testing, security review, repair, and human approval.

    Programme 02

    Runtime Governance for Tool Using Agents

    Objective: ensure that tool calls reflect authorised intent, remain within an explicit scope, and leave evidence sufficient for audit and recovery.

    Technical methods

    • Permission and intent semantics
    • Sandboxed execution and runtime monitoring
    • Provenance and supply-chain analysis

    Selected assets

    • Fine-grained malicious component detection (ASE 2023)
    • Repackaged Apps Detection (SANER 2019)
    • XDebloat: feature-oriented application debloating (TSE 2022)

    The next research frontier is consequence-aware governance that connects user intent, delegated authority, runtime behaviour, and confirmation requirements.

    Programme 03

    Evidence Based Evaluation of Agentic Workflows

    Objective: support deployment decisions with reproducible evidence about correctness, security, cost, environmental impact, and human oversight.

    Technical methods

    • Benchmark and failure taxonomy design
    • Runtime traces and workflow reconstruction
    • Cost-, carbon-, and review-aware measurement

    Selected assets

    • Characterising Bugs in Jupyter Platform (EASE 2025)
    • Low-code programming empirical study (JSS)
    • Human-in-the-loop defect prediction study (SCP 2025)

    The next research frontier is a shared evaluation record that connects output quality with runtime evidence, review effort, inference cost, and deployment risk.

    Public Confidence and Reduced Fear

    AI generated software increasingly influences services, devices, workplaces, and digital infrastructure. People experience fear and uncertainty when they cannot determine what an AI system changed, why an agent performed an action, whether private information was exposed, or who is responsible for a failure.

    This research addresses that uncertainty through a concrete causal mechanism: software behaviour becomes testable, agent actions become auditable, permissions become explicit, runtime evidence becomes reconstructable, and unsafe outputs can be rejected. These controls support digital trust, safer participation, accountability, and protection from hidden harms without overstating outcomes that still require validation in practice.
