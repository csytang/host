    Research Agenda

    Trustworthy AI for Software and Agentic Systems

    Secure and Verifiable Agentic Software Engineering

    Yutian Tang studies how AI-generated software and tool-using agents can be made secure, verifiable, accountable, and deployable. His research uses software engineering, program analysis, software security, runtime evidence, and empirical evaluation to determine when AI-generated software and agent actions should be trusted, constrained, or rejected.

    Yutian Tang develops software engineering and security methods to determine whether AI-generated software and agent actions are authorised, verifiable, and accountable.

    Main research architecture

    Research Direction 1

    Agent Permission and Intent Semantics

    Core question: Whose intent should control an AI agent’s permissions?

    Authenticating a user, agent, or tool is not sufficient. A system must also establish the origin of intent, whether an action was caused by authorised intent, whether it matches the original task, whether its scope is permitted, and whether its consequences require further confirmation.

    This direction studies user authorisation, delegated authority, action, scope, and consequence mismatch, permission semantics and laundering, Model Context Protocol security, tool governance, runtime permission enforcement, and auditability. Prompt injection is one risk within a broader problem: actions can be permitted by a system while remaining unauthorised by the user.

    Selected evidence

    • MCP-SandboxScan — WebAssembly-based secure execution and runtime analysis for Model Context Protocol tools

    Research Direction 2

    Semantic Validation of AI-Generated Software

    Core question: When should AI-generated software be trusted?

    Code generation is an object of validation, not an independent capability race. Syntactically correct code can still contain behavioural defects, security vulnerabilities, incorrect assumptions, weak tests, compatibility failures, or security regressions.

    This direction combines program reasoning, static and dynamic analysis, taint analysis, software testing, code generation, debugging, repair and patch validation, compatibility and configuration analysis, test adequacy, and intent-to-code consistency. Generated artefacts must be analysed, tested, constrained, and sometimes rejected.

    Selected evidence

    • Artemis — inter-procedural, path-sensitive taint analysis assisted by large language models
    • LLM-CompDroid — repair of configuration compatibility bugs in Android applications
    • Beyond Coverage — automatic test-suite augmentation for enhanced effectiveness
    • ChatGPT versus search-based software testing — comparative assessment of unit-test generation

    Research Direction 3

    Runtime Evidence and Accountability for Agentic Workflows

    Core question: What evidence is required to hold an agentic system accountable?

    Task completion alone does not establish trustworthiness. An agent may complete a task while reading unnecessary files, exposing private data, using an unauthorised service, introducing a vulnerability, or relying on an unreproducible execution path.

    This direction studies runtime monitoring, execution provenance, evidence reconstruction, workflow reliability and analysis, benchmark design, human oversight, reproducibility, failure analysis, security exposure, inference and environmental cost, and deployment decisions. Cost and carbon are evaluation dimensions within accountable deployment, not separate research directions.

    Selected evidence

    • FuseChain — runtime evidence reconstruction for software supply-chain attacks
    • Empirical study of agentic workflows in the n8n ecosystem
    • SecBenchLLM — an ongoing security-evaluation benchmark project
    • LLM EcoBench Lite — an ongoing cost- and carbon-aware evaluation project
    • Characterising bugs in the Jupyter platform

    Application and validation layer

    Application Domain: Mobile and Software Ecosystem Security

    Mobile and Android ecosystems provide realistic validation environments for permission boundaries, sensitive data flows, third-party dependencies, application repackaging, compatibility failures, malicious components, software supply-chain risks, and runtime behaviour. These settings connect the main agenda to concrete questions in trustworthy AI, agent security, software validation, and software ecosystem governance.

    Selected examples

    • WhisperCatcher — unauthorised and encrypted private-data transmission
    • Mobile Sharing Service Abuse
    • App Link Attack
    • Android App Bundle Analysis

    Supporting method

    Research Method: Empirical Measurement and Benchmark Design

    Empirical software engineering provides the methods needed to build large-scale datasets, failure taxonomies, benchmarks, controlled evaluations, reproducible evidence, developer and workflow studies, human-oversight evaluations, and reliability measurements. It supports all three primary directions by testing whether permission controls, validation techniques, and accountability evidence work under realistic conditions.

    Examples include the n8n workflow study, Jupyter bug characterisation, security benchmark design, and controlled comparisons of generated tests and software artefacts.
